# AGENTS.md

Agent instructions for working in this repository.

## What this repo is

Source for **m2ng.github.io**: a personal site made of two apps, deployed to the
`gh-pages` branch by GitHub Actions:

- **CV** (`apps/main`) — a static CV generated by a small Bun script. The output
  is plain HTML/CSS and **must render without JavaScript**.
- **Blog** (`apps/jekyll/m2ng`) — a Jekyll site (minima theme).

Default branch is `master`; the deploy target is the `gh-pages` branch (do not
edit it directly — it is force-pushed by CI).

## Layout

```
apps/main/                 The CV (static site generator, Bun)
  build.js                 Generator: data/ + styles/ -> <repo>/build
  serve.js                 Local preview server (Bun.serve), serves <repo>/build
  package.json             Bun package (scripts: build, preview, clean)
  bun.lock                 Committed for reproducible installs
  data/                    CV content — single source of truth (JSON)
    experience.json        Jobs + degrees, in order
    skills.json            Skill groups
    tags.json              Tag vocabulary per section (name + tooltip)
  styles/                  Styling — single source of truth (SCSS)
    base.scss              Compiled first, then app.scss (concatenated)
    app.scss               CV layout + component styles
  public/                  Static assets copied verbatim into the build
    favicon.ico, robots.txt, manifest.json, assets/MatthewNg_pic.jpg
apps/jekyll/m2ng/          The blog (Jekyll + minima); built by CI in docker
apps/responsive-images/    Docker helper: regenerate responsive blog images
apps/screenshot/           Docker helper: site screenshots
scripts/
  build.sh                 Local: build CV (Bun) + blog (Jekyll) into ./build
  jekyll.sh                Jekyll: make | dev | build
  deploy.sh                Manual: copy ./build to gh-pages and push
.github/workflows/main.yml CI: build CV + blog, assemble, deploy to gh-pages
build/                     Gitignored build output (CV site at the root)
```

## Tooling: Bun, not Node

The CV is built with **Bun** (`~/.bun/bin/bun`). Plain `node` may not be on
PATH. Always invoke Bun explicitly, e.g. `export PATH="$HOME/.bun/bin:$PATH"`.
`apps/main` depends only on `sass` (pure-JS dart-sass); everything else is
`node:` built-ins that Bun provides.

## Common commands (CV)

```sh
cd apps/main
bun install              # after package.json changes
bun run build            # emit static site -> <repo>/build (override: CV_OUT=/path)
bun run preview          # build + serve at http://localhost:4321
bun run clean            # rm -rf <repo>/build
```

## Editing CV content

All CV text lives in `apps/main/data/*.json` — never edit generated HTML.

- `experience.json`: each entry has `nature` (`"job"` | `"degree"`), `visible`,
  `title`, `place`, `url`, `time`, `effective` (currently employed / in school),
  and optional `details` (the bullet rows). Degree entries carry
  `education_details` (`type`, `major`, `grade`).
- **`details` rows (desc-items)** are a plain array of strings, one row per
  bullet. Row grammar:
  - `!!` prefix (optional) → highlight the row.
  - A token starting with `#` is a tag reference, e.g. `#kubernetes`. Tags are
    resolved against `tags.json` **for that section** (`experience` or
    `skills`) and rendered as inline `<span class="tag">` (with tooltip when
    defined).
  - Everything else is literal text.
  - Tokens are joined with **single spaces**, so the emitted HTML keeps each row
    as one contiguous run of text — preserve that: don't introduce constructs
    that fragment a row.
- `tags.json`: `section` → `tags[]` with `name` (the token after `#`, spaces
  replace underscores) and optional `tooltip`.
- After any data/style change: `bun run build` and verify in a browser before
  committing/pushing (see "Verify" below).

## Editing CV styling

SCSS only, in `apps/main/styles/`. `build.js` compiles `base.scss` then
`app.scss` (expanded) and concatenates them into `build/assets/index.css`.
Keep the existing class names/structure — the DOM is reproduced 1:1 from the
original React app and the styles depend on it.

## Invariants (do not break)

1. **No JavaScript**: the built `index.html` must contain zero `<script>` tags
   and no `.js` references. The CV must render fully with JS disabled.
2. **DOM stability**: the generated markup structure/classes are what the SCSS
   targets — change markup and styles together if you must.
3. **Build output location**: CI and local scripts expect the CV at
   `<repo>/build` (env override: `CV_OUT`). Don't change the emit layout
   (`index.html`, `assets/index.css`, `assets/MatthewNg_pic.jpg`,
   `favicon.ico`, `manifest.json`, `robots.txt`) without updating
   `.github/workflows/main.yml` and `scripts/` accordingly.
4. The **blog** is out of scope for CV work; don't touch `apps/jekyll/**`
   unless explicitly asked.

## CI / deployment

- Trigger: push to `master`. A commit message containing **`no-ci`** skips the
  pipeline.
- Jobs: `build-cv` (Bun via `oven-sh/setup-bun`, `CV_OUT=$PWD/build bun run
  build`), `build-blog` (Jekyll in docker), then `build` downloads both
  artifacts, assembles `build/` (CV at root, blog under `blog/`), and force-push
  it to `gh-pages` over SSH.
- The deploy SSH key is the repo secret **`CI_PRI`** (base64 of a private key;
  the matching public key must be a repo **Deploy key with write access**).
  "Permission denied (publickey)" in the Deploy step means that registration is
  missing or was rotated.
- Use `actions/upload-artifact@v4` / `actions/download-artifact@v4` (v3 is
  auto-failed by GitHub as deprecated).
- Verify runs at
  `https://github.com/m2ng/m2ng.github.io/actions` (run logs require auth).

## Verify (CV changes)

```sh
cd apps/main
bun run build
# sanity in the emitted HTML:
grep -c "<script" ../../build/index.html          # must be 0
# spot-check key phrases from data/ are present in ../../build/index.html
```

Then render in a real browser: `bun run preview` and open
http://localhost:4321, or headless-screenshot:

```sh
"$HOME/.cache/ms-playwright/chromium-*/chrome-linux64/chrome" \
  --headless=new --no-sandbox --disable-gpu \
  --window-size=860,1450 --screenshot=/tmp/opencode/cv.png \
  http://localhost:4321/
```

Compare against the previous look — the site should be visually identical
except for the intended change.

## Conventions

- **Atomic commits**: one logical change per commit (content edits, styling,
  tooling/CI each in their own commit).
- **Push only after verification**: build + browser check locally first; the
  remote push is what triggers the live deploy.
- Keep this file current when the layout, tooling, or workflow changes.
